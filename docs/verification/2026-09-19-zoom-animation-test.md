# 缩放动画测试时序排查

> 本记录针对较早的工具栏动画测试时序失败。随后用户反馈的连续放大卡顿另有棋盘重绘性能原因，见 [透明棋盘格与连续缩放修复](2026-09-19-transparency-grid.md)。

## 结论

`testToolbarZoomRemainsVisibleThroughSwiftUIUpdates` 的失败来自测试取样时机，未发现需要修改的缩放实现问题。本次保留产品代码，仅调整这项真实鼠标事件集成测试。

## 证据与代码检查

- 原测试在工具栏点击后固定等待 55 ms，就要求画面处于动画中途。实际路径经过 SwiftUI 更新、主队列异步命令执行与 Core Animation 提交，这几步不与点击时间同步。记录中目标已更新为 1.25，但取到的呈现比例仍约为 1.000001。
- 交替缩放的范围原先使用点击前的画面比例。记录中一次反向点击前比例为 1.02436，命令实际接管时旧动画已到 1.03201；以点击前比例为上界会误判合法接管。
- 检查 `applyToolbarZoom`、`visualTransform`、`animateTransform` 与 SwiftUI 命令写回路径：缩放目标累计、读取同一呈现帧的几何与变换、同 key 动画替换、同方向速度接续及反向速度处理均保留现有逻辑。其他接管、速度、连续请求、旋转与 Reduce Motion 测试通过。

## 测试调整

- 保留通过 `NSApplication` 发送真实工具栏鼠标事件的路径，并使用看图工具栏实际的水平内边距计算点击坐标。
- 以有超时上限的状态等待替代固定动画等待：确认请求已消费、目标已累计，再检查呈现层已经使用新目标尺寸。
- 从已安装动画的 `fromValue` 得到真实接管起点，继续检查中间帧、方向单调性、范围和最后落点；没有放宽原有比例误差阈值。
- 每次连续点击前必须观察到上一段动画的中间帧，避免测试退化为动画结束后的独立单次点击。

## 验证

- 完整 `swift test`：299 项 XCTest、3 项 Swift Testing（其中透明像素测试包含浅色与深色两个用例）全部通过。
- 调整后的原失败测试单独连续运行 10 次，全部通过。
- 在临时源码副本中，向 `hitTest` 注入原先的 `interruptMotion()` 错误行为后，新测试因累计目标不成立而失败，确认仍能捕获实际交互回归。
- 临时时间日志和故障注入均已清除。
